## Numerical implementation assessment

The inspected numerical bytes are unchanged from the earlier pinned experiment:

- `candidate.py` SHA-256 `70924d2b7ac40367e9ae4abaee624dd6c0b85796a62c5445b0694f2240fac606`
- `worker.py` SHA-256 `d6dff0e19f8647157d55ac3d6ba37ddaeaa7ce192ba25313d921d53298607fa9`
- `bridge.mjs` SHA-256 `0d650987bac5343c28a303655afc0c02c2eec8a383e8abe2388f27ce74b66262`

`decode` admits only nonnegative encodings no greater than positive one. Positive zero maps to lattice integer 0; negative zero, negative values, infinities, NaNs and values above one are refused by the domain check. The subnormal and normal branches implement the exact integer numerator on the `U = 2^1074` lattice.

`transform` sorts by exact lattice value and original member position, computes `(m-rank)*P` with exact integers, applies a running maximum, clips at `U`, and maps adjusted values back to original member order. Equal input p encodings receive equal adjusted exact values because the first member in a tied block has the largest rank multiplier for that block and the cumulative maximum carries forward. Tie ordering is a deterministic project convention; it does not create a statistical claim.

`project` performs one nearest, ties-to-even binary64 projection of the exact adjusted value `A/U` without intermediate floating arithmetic. Exact adjusted integer comparison remains essential because different exact adjusted values can share a display encoding.

For `0 < alpha < 1`, the adjusted-value condition is equivalent to the ordinary Holm sequential comparisons under the reviewed assumptions. At `alpha = 1`, clipping can break that equivalence, so the candidate correctly accepts no alpha and emits no rejection/significance boolean. Binary64 `0.05` is not silently treated as exact rational `1/20`.

`worker.py` rehashes and executes the pinned `candidate.py`, accepts only the private generated carrier, restricts the promoted slice to 3..120 members, and returns exact adjusted hex plus display hex. `bridge.mjs` adds the public-side preparation discipline: strict JSON, D0 validation, all-pairs 3..16 group scope, complete expected-context binding, member order, source-hypothesis uniqueness, exact adjusted and display comparison. The private worker carrier drops source-hypothesis IDs only after the full binding and origin tuple checks have already run.
