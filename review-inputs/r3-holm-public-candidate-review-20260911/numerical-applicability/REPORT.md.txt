## Implementation argument

`decode` first restricts an eight-byte unsigned encoding to at most the encoding
of one. This excludes all sign-bit values, infinities, NaNs, and numbers above
one. Its subnormal and normal cases give exactly the IEEE field-derived lattice
integer from the reused source review. Positive zero maps to integer zero.

`transform` sorts the exact integers, using original index only to resolve ties.
At rank i it forms the exact integer product `(m-i+1)*P_(i)`, takes the running
maximum and clips at U. Since all terms are nonnegative, clipping each scan step
is equivalent to clipping the final prefix maximum. The explicit inverse
assignment returns values in original member order. For a tied block, its first
product is largest within that block, so all tied members receive the same
prefix maximum after clipping.

For `0<alpha<1`, an adjusted value is at most alpha exactly when every earlier
rank product is at most alpha. This is Scheme 1's sequential rejection rule.
Clipping can make that equivalence false at alpha=1: three p values of 3/4 all
have clipped adjusted value one, while the first Scheme 1 comparison at level
one fails. The operation correctly accepts no alpha and emits no significance
boolean. This review also retains the distinction between binary64 0.05 and the
exact rational 1/20.

`project` shifts to at most 53 significant bits, compares the discarded integer
remainder with its exact midpoint, and increments on greater distance or an odd
tie. It then handles a significand carry before assembling the bits. Near zero
the integer lattice already represents every subnormal exactly; at the upper
endpoint clipping keeps the argument at most one. No intermediate float rounding
enters this implementation. Exact adjusted integer comparison remains necessary:
distinct values can share one display encoding.

The generic module allows 1..1024 members, but the bridge and worker restrict
this slice to 3..120, with the bridge requiring `k*(k-1)/2` for 3..16 groups.
Those generic extra sizes are not added to the candidate support domain. The
bridge checks full expected declaration/input equality and source-hypothesis
tuple uniqueness before reducing the private worker carrier. Dropping the
source-hypothesis field from that private arithmetic message does not itself
discard the earlier full-context comparison. This is a read-through assessment
of the bridge's ordering, not a new complete D0/adversarial-wrapper review.

## Independent checks

`independent_checks.py` authored six fixed rational expectation families before
loading candidate code. For small families its oracle enumerates every nonempty
intersection, assigns the Bonferroni local level `min(1, |S|*min(p in S))`, and
takes the maximum over intersections containing each hypothesis. It does not
repeat the candidate's sorted running-maximum algorithm. For larger families it
uses a separate threshold/set-cardinality characterization, cross-checked against
the complete enumeration in every small generated case.

The projection oracle binary-searches positive binary64 encodings using
`struct.unpack` and exact `float.as_integer_ratio()` values, then compares exact
distances to adjacent floats and applies low-bit parity. It does not reuse the
candidate's significand-shift rounding algorithm. A third cross-check uses
Python's rational-to-float conversion. These are standard-library software
oracles, not hardware-certification evidence or an independent vendor runtime.

Recorded results: **21,763 explicit checks passed**, both normally and with
Python `-O`; the two result files are byte-identical. Principal coverage:

- 408 exact encoding/lattice checks and 10 invalid-input controls.
- Six hand-authored families, 240 closed-testing families with 3..8 members,
  and 28 all-pairs families covering every group count 3..16.
- 1,547 exact sequential-test comparisons in the stated alpha domain, plus
  tied-member equality, the alpha=1 counterexample, and a display collision.
- 9,295 projection cases and the same number of rational-to-float cross-checks,
  including midpoint parity, adjacent values, exponent carries, subnormal/normal
  boundaries, and one; five invalid projection arguments are refused.
- Fourteen actual private-worker executions, seven fixed/max-size inputs in
  ordinary and optimized isolated Python, compared against the independent
  expected exact integers and display bits.

These are bounded tests and a code argument, not exhaustive enumeration of all
binary64 families. The seed is recorded; checks use explicit exceptions and do
not disappear under optimized Python. There was no broad replay of old repository
regression suites, no cgroup experiment, and no claim about current CI state.
