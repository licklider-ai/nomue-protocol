Date: 2026-09-11 UTC  
Review scope: safe preservation of fixed experimental research and development
assets under `governance/drafts/**` and `review-inputs/**` only.

## Disposition

**ARCHIVE GO for all five stacks below.** This is permission to preserve the
fixed records as explicitly experimental, informative material. It is not a GO
for a reference implementation, supported execution, a public check, a supported
domain, interface freeze, methodology adoption, identifier issuance, gate closure,
or release.

The five stacks contain useful negative results, exact-input arithmetic,
probability-enclosure derivations, repaired evidence checks, fixed review
correspondence, source-limit records, resource probes, and later composition and
consumer experiments. Their paths remain outside authoritative and reference
implementation surfaces. Every numerical and policy hold stated below remains in
force after archive integration.

## Reviewer provenance and method

This review was performed in a separate task by an OpenAI Codex agent configured
as `gpt-5.6-sol`. No served-build or model-binary attestation was available. No
human review is claimed. I did not author or repair any reviewed packet, did not
use a subagent, and did not modify the shared repository. Inspection and focused
execution used an isolated local clone and detached worktrees.

I did not inspect the original NIST/DLMF pages or the licensed IEEE PDF. Source
connections in this review are reuse assessments of the fixed reports and ledgers,
not new primary-source findings. Where a packet says a prior investigator directly
inspected a source, this report records that claim and its provenance limits rather
than independently reattesting it.

The repository `AGENTS.md` and its ordered Charter, Authority, authority manifest,
requirements registry, ID policy, and RFC Research Gate were read before the
assets. The decisive boundary is the RFC carve-out for disposable exploratory
spikes. Archive placement does not promote their behavior. Any later use in
authoritative semantics or reference implementation behavior reopens the applicable
Research Gate and implementation review.

## Integration order and promotion holds

Integrate the stacks in the numbered order above. Within each stack, preserve the
listed commit order. The primary-method/IEEE and rational-composition branches
both start from the repaired checker input; integrating the source stack first and
the composition stack second avoids ambiguity while remaining content compatible.
The complete-output/consumer stack uses separate directories but should follow its
pinned arithmetic, tail, source, and composition records so its references are
available in the archive.

After integration, retain all of these holds:

1. No code in these packets is a supported reference implementation or public
   verifier behavior.
2. No supported observation count, rational width, endpoint size, platform,
   latency, memory, tolerance, or precision schedule is established.
3. Exact SSE zero, positive SSE that projects to zero, positive F/tails that
   project to zero, and values above maximum finite remain separate states.
4. Signed-zero input identity and arithmetic zero semantics remain distinct.
5. Fixed-enclosure containment is a conservative contract, not a general
   mathematical truth-inclusion decision.
6. The bounded methods/source reports do not approve later adapters, wrappers,
   consumers, output policy, or whole-release semantics.
7. User-supplied adversarial receipts without reviewer/model identity remain
   attributable testimony only. No human review is inferred.
8. Any promotion into authoritative semantics, public checks, conformance
   expectations, or reference implementation behavior requires the applicable
   Research Gate, independent implementation/oracle evidence, public contract
   coupling, and steward process at that later fixed input.
