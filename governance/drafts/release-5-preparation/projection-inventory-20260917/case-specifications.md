## Construction and evidence rules

Use the following local construction recipes only after their prerequisites are
accepted. These names and sample IDs are explanatory labels, not Protocol IDs:

- Independent recipe: two declared groups, three distinct units/observations per
  group, continuous outcome, opaque unit label, independent grouping, no pairing,
  no repetition, no declared clustering, all supplied observations in the analysis.
- Paired recipe: two conditions, three declared pairs and one observation per
  condition in each pair. Retain separate experimental-unit and pair carriers and
  owner-valid links. Use `within_pair_only` as a qualified declaration, not a
  Boolean shared with the independent recipe.
- Multi-group recipe: three declared groups and owner-valid unit/observation links;
  two uniquely identified analyses A and B over the same supplied dataset. A uses
  all observations; B uses a different explicit population only if the owning
  successor admits it. Otherwise run the order/binding variant with distinct
  analysis identities and admitted populations, keeping the unequal-population
  variant blocked. Repetition, clustering and pair applicability need separately
  accepted Profile-owned meanings/carriers.

Every recipe also needs the exact accepted Contract, Profile, Record, report,
check and bundle versions. Supply admissible, ordinary finite outcomes sufficient
for the owning checks; no numerical truth values are invented here. Baseline timing
is `unknown` unless a case specifies otherwise. The mapping's eight cells follow
[the conditional draft](conditional-mapping-draft.md) and their meaning stays
conditional on its named research/owner decisions. Before execution, replace every
recipe with saved input bytes and a reviewed, fully enumerated expected report.

For mutation cases, change only the named condition plus mechanically necessary
revision/digest metadata. Validate that the intended stage is reachable; if another
owning condition fails first, repair the construction or keep it blocked rather
than crediting the intended assertion. A corrupted output is tested as a report
validation/comparison case, not as input accepted by a verifier.

For every executable variant retain baseline and mutated input hashes, exact
accepted configuration and mapping reference, expected evidence authored before
execution, actual evidence, invocation, tool/source commit and comparison result.
A successful R5 report includes its exact subject/revision/analysis, eight cells
and concrete source pointers, consumed identities, mapping reference, timing,
actual dependency result and the eleven-item non-claim reference. Call this the
complete evidence set below; it does not assert integrity or numeric-check success.

Blocked/error results follow the [outcome contract](record-and-report-draft.md#execution-state-contract):
post-conformance timing is retained; no computed projection on dependency blocking;
no outcome for a non-completed check and no fabricated missing evidence. A report
validator may need Record and accepted configuration inputs to detect cross-artifact
inconsistency; schema shape checking alone cannot establish all these assertions.

## Prerequisite notation and reasons

- **S**: exact accepted successor surfaces, family admission, bundle/check and
  mapping definition; applies to every proposed R5 runtime/report case.
- **D**: acceptance of the timing/reference proposals in
  [decision-binding-proposal.md](decision-binding-proposal.md).
- **G**: research/owner disposition of the affected mapping meaning, especially
  pair applicability, qualified repetition and R3 population/carrier semantics.
- **E**: accepted outcome, propagation or reason-code encoding. Until accepted,
  retain the stated prohibition but do not invent an exact machine outcome/code.
- **L**: historical pins and invocation environment captured before integration;
  future replay is not performed by this preparation pass.

Each row names the owning reason: RFC =
[opening RFC](../opening-rfc-candidate.md); Mapping =
[conditional mapping draft](conditional-mapping-draft.md); Binding =
[decision/reference proposal](decision-binding-proposal.md); Outcome =
[Record/report draft](record-and-report-draft.md); Surfaces =
[retained schema observations](report-surface-followup.md). These are references
for planning, not a claim that all draft rules are already authoritative.

## Completion boundary for this preparation pass

The 37 plans now distinguish runtime, report comparison, configuration/admission,
producer-instruction and historical replay tasks. Their per-row prerequisites are
intentionally unresolved where source, owner or successor decisions are missing.
Exact fixture bytes, public IDs, machine reason codes and executed results wait
for those prerequisites; creating placeholders that look issued would not finish
them honestly. CI on these prose documents is not 37 passing R5 tests.

The author checked label coverage, stage reachability assumptions, per-analysis
binding, reference mismatch cases and the distinction between observable bytes and
hidden event history. Independent diff review is a separate retained record.
After that review and necessary repairs, stop this bounded task while source
acquisition proceeds. No change to R5-P2/P3/P5/P6/P7 or opening-only P8 is made.
