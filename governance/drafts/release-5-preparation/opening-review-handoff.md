# Release 5 opening-proposal independent review handoff

Read the repository `AGENTS.md` and its required governance documents first.

Resolve the target branch once and record its full commit, parent, tree and blobs for:

- `governance/drafts/release-5-preparation/README.md`;
- `governance/drafts/release-5-preparation/opening-rfc-candidate.md`;
- `governance/drafts/release-5-preparation/research-commission.md`;
- `governance/drafts/release-5-preparation/public-discussion-readiness.md`; and
- `governance/drafts/release-horizon-r3-r20.md`.

Stop on identity drift. Review the fixed target rather than a moving branch.

## Review questions

1. Does the proposal remain inside the Charter's Layer 1 scope by specifying stored
   analytical decisions and verification evidence, without standardizing an agent
   command, dialogue, transport, authentication flow or product orchestration?
2. Is the proposed distinction between exact bundle dispatch and scientific
   Contract selection correct and unambiguous?
3. Does the initial three-family boundary avoid silently adopting unresolved Release
   2 or Release 3 meaning, and are those dependencies genuinely conditional?
4. Is successful selection coherent and independently checkable, and does excluding
   clarification, unsupported-design and inadmissibility workflow states from the
   first Record slice avoid hidden Layer 2 semantics without omitting necessary
   Protocol evidence?
5. Does the proposal preserve old bundle meanings, report semantics, canonicalization
   and pinned conformance results?
6. Is STABLE-INTENT a defensible anticipated highest tier, or does the proposal
   necessarily alter CORE meaning?
7. Does the Research Gate commission cover the external scientific facts needed
   before opening? Name missing primary-source questions precisely.
8. Is moving rank-based procedures to a later horizon coherent with the dependency
   order, without presenting that planning update as a scientific rejection?
9. Which issues must close before opening, and which may remain explicit holds during
   public discussion?

## Return format

Create an English report with exact inputs, findings classified as BLOCKER,
SHOULD-FIX or NICE-TO-HAVE, gate-by-gate disposition for R5-P1 through R5-P8,
recommended repairs, source-access result and independence disclosure.

The reviewer does not open the public issue, issue identifiers, modify normative
artifacts or claim steward approval. A self-review or an additional pass in the
authoring context is not independent clearance.
