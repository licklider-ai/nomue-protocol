## Concrete remaining registry incompatibilities

The four existing meta-schemas for public checks, interpretation bundles, public
surfaces and reason codes reject the new HTTPS check/bundle/profile identifiers
and/or capability Requirement prefixes. This is distinct from the requirement
registry meta-schema, which already supports the adopted extensible grammar.
The packet's meta-schema previews extend only those lexical validation positions,
preserve legacy alternatives, and reject noncanonical aliases. They are unissued
migration candidates. Passing them does not establish integrated tooling support.

Before authoritative integration, check every consumer of those registries,
including public-surface path resolution, bundle validation, generated views,
TypeScript types, conformance loading and exact dispatcher selection. Freeze the
complete final delta only after this join and its review are complete. No existing
registry or validator is edited by the preparation packet.
