## Meta-schema changes are concrete but bounded

The previews retain all existing registered rows and allow the adopted capability
Requirement syntax and canonical HTTPS check/bundle/profile spellings. The
successor revision syntax here covers the proposed candidate tokens; it does not
claim to define every future family revision alphabet. The final issuer policy
and tooling need a common bounded representation rather than four divergent
future regexes. Existing legacy grammar is retained, not silently tightened.

Public checks add a distinct prerequisite propagation option because candidate
not_run rows carry prerequisite_failed, whereas the existing registry option
requires copying the blocking reason. Claiming the old option would misdescribe
the current candidate. Existing check rows retain their old policy.
Structured Holm comparison constants reproduce the candidate check policy.
Bundle rows explicitly connect Contract, expected-context and report destinations.
Those additions are versioned proposal deltas, not automatically issued metadata.

Refusal public-surface applicability lists the proposed bundle only as a capability
of the prospective verifier. It does not select the refusal schema by a Record
field: malformed/unknown/pre-routing inputs receive the invocation's same
verifier-level output protocol. The candidate-only refusal adapter does not
establish the final multi-bundle output protocol or legacy compatibility.

## Fixed conformance expectations

FIXTURES.json names nine proposed fixture IDs and hashes both Record and separate
expected context. author_fixtures.mjs generates only author-specified examples;
it imports no candidate implementation. Expected rational families are fixed
before verification: (0,1/4,1) -> (0,1/2,1), tied 1/8 -> 3/8, and subnormal
lattice (1,2,3) -> (3,4,4). An exact-numerator mutation preserves the displayed
value to test why display equality is insufficient. Context, D0 relation,
negative-zero-domain, old-candidate-bundle and raw-duplicate failures have explicit
stage/reason/forwarding expectations. test_fixtures.mjs never writes inputs or
expectations. These nine cases add independent fixed numerical targets; they do
not replace the wider envelope, bounds, identity or real-host controls.
