## Research-gate assessment

GitHub review lists and human reviews are not the complete research record. Conversely,
a contributor's description of independent work does not prove its independence.
RFC.md requires an independent pass and, for statistical/numerical methodology,
a separate LLM/model primary-source review. It does not require a human GitHub
approval on every candidate PR. The earlier separate-context admission review is
not used here as proof of a separate numerical model. The #322 closing archive
explicitly records a configured gpt-5.5 context, with served build/author-model
uncertainty; this remains a bounded disclosure, not upgraded by this repair.

No numerical method changes in this patch. This author-context repair closes
concrete implementation/evidence defects only; it does not retrospectively certify
research-gate compliance. Before formal adoption, an accountable decision still
needs to establish sufficient independent evidence for each decision-bearing
methodological claim, using existing records where actually sufficient and obtaining
missing evidence where not. Missing initial files or identities remain explicit.

## CI and trust boundaries

The workflows run on disposable GitHub-hosted machines with contents:read and no
pull_request_target trigger. Root cgroup tests still execute reviewed repository
Python. Action tags are inherited, not SHA-pinned, and no new supply-chain guarantee
is claimed. Branch protection and required-check configuration have not been
established by this patch. The contributor checks all relevant jobs before merge;
a workflow name alone does not establish a mandatory repository rule.

CI freshness is intentionally conservative: no path filters on active R3 workflows.
Source pins are reviewed and refreshed explicitly, never repinned automatically to
turn a failing check green. The new map performs regression comparisons without
rewriting its own inputs. Standard CI alone still does not certify all draft semantics.
