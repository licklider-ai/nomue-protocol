## Machine-readable claim binding

Each raw fixture includes its input SHA, category, expected final fields, source keys,
independence level, derivation note and `candidate_output_used_to_derive_expectation:
false`. Quantities inherit the numeric claim from their fixture and identify their
exact vector id and ordinal. Source keys resolve to commit/path/blob/SHA. These
flags record construction history; they do not certify correctness. The overflow
fixture's independently authored final-state mapping is known defective and retained.

Level C numerical reuse does not call the original author oracle (which imports a
candidate comparison subject). T10 reads the previously independently checked vector
bytes. The G5 output log is not an input to the builder. Reviewed cost source and
scientific source are distinguished from author acceptance/decision documents.

## Analytic components and shared dependencies

Projection components are exact IEEE field values, adjacent rational midpoints,
ordinary inexact values and explicit D04 refusal. Negative mathematical tiny targets
may project to internal zero; no public -0 token is introduced.

For component-only tails n=2, the existing reviewed beta integral specializes to
`F=4t^2/(1-t^2)` and `p=1-(3t-t^3)/2`, for rational t in [0,1). A second positive
factorization, `(1-t)^2*(t+2)/2`, checks the exact value. Exact rounding-cell endpoint
inequalities verify every frozen binary64 decision, including either side of a
midpoint, subnormal and underflow. Shared Fraction/integer primitives and CPython
conversion are disclosed; this is analytic specialization of reviewed mathematics,
not independent implementation certification. These components are not raw-Record
realization, J-cost membership or integrated-delivery evidence.

The builder imports only allowlisted Python standard library modules. Its two
subprocess channels read pinned Git source and run the input-only sealer. The sealer
uses locked canonicalize and node:crypto, not candidate validation/numerical code.
The static audit is saved in SELF-CHECK. Candidate comparison code is separate and
can import T09; it is never an expected-generator dependency.
