# EC4 support mapping

This is an unissued candidate mapping, not a public support announcement.

## Four different sets

1. **Scientific/admissible:** inputs meeting the candidate balanced replicated
   2x2 structural and model applicability prerequisites. A declaration is not
   independent proof that a scientific model is true.
2. **Public-supported candidate domain:** J-cost(B,S-C) with the fixed B,
   computability and Z-B representation/eligibility conditions. This is a
   resource-independent candidate semantics definition, not an issued bundle.
3. **Candidate reference support:** option **B**, an unissued reference safety
   profile and validation basis. The profile defines a bounded attempted-execution
   envelope. Evidence establishes successful numerical execution only for the
   listed finite cases; it does not establish completion for every public member.
   Failure containment applies separately from numerical completion claims.
4. **Observed/tested:** the exact raw corpus hashes and completed outcomes in the
   saved Linux measurements. This set is finite, host-specific evidence.

The current issued reference does not dispatch the R4 candidate as an issued
supported bundle. Main includes the historical research supervisor/worker, not a
production S-C integration. Historical transport requires 2<=n<=65, and the worker
uses the earlier tail consumer and numerical guards. That is a research
implementation limitation, never an additional public-domain predicate.
G5 remains research-only in its pinned divergent snapshot.

## Gaps and sequencing

- **Implementation:** G5/strict R4 dispatch, the report/refusal adapter and selected
  resource architecture are not issued production integration. T08 owns integration
  in the shared public verifier development home, subject to normal change control.
- **Validation:** neither the finite corpus nor G5's proof of bounded abstract work
  proves execution within this host's seconds/bytes throughout J-cost. A universal
  completion envelope is unestablished. T08 needs appropriate broader evidence.
- **Host:** only the recorded Linux x86_64 CPython 3.12.14 image/kernel has new
  full-invocation evidence. Windows input preparation is supplemental, not Linux
  validation; other runtimes/OSes/kernel controllers are unvalidated.
- **Resource profile:** accepted public raw Record shapes and witness encodings can
  meet J-cost but exceed a reference byte cap. These are reference refusals, not
  public-domain false. The profile and corpus do not claim equality of the two sets.
- **Refusal/report contract:** the artifact is a research receipt. Mapping all
  execution failure causes to the issued verifier-level refusal schema/reason codes,
  and transactional delivery/CLI behavior, remain production integration work.
  No new public identifiers are created here.

## Version boundary

Changing J-cost, B, Z-B or S-C semantics affects the Public Check/version/bundle
contract. Public numerical decisions and comparisons are owned by check versions.
Changing CPU/wall limits, memory/output caps or validated hosts does not
**automatically** change that Public Check version when the numerical decisions
stay identical; it still needs security evidence and change control. Changes to
the public report/refusal/CLI interface need their own compatibility assessment.
No automatic public-discussion clock reset rule is assumed or adopted.

## Candidate statement

The public candidate is the fixed resource-independent J-cost(B,S-C)/Z-B domain.
The reference candidate is an unissued safety profile with a named validation host,
finite completion witnesses and separately tested refusal/containment behavior.
The main historical worker has narrower and different numerical capability.
There is no whole-domain equivalence claim, no promotion of the research harness,
and no T08 implementation in this work.
